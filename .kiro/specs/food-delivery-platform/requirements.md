# 需求文件

## 簡介

本功能為外送平台後端系統，負責處理訂單從下單到送達的完整生命週期。系統管理顧客、餐廳、外送員間的互動，並具備完整的例外處理與 Log4j 2 日誌功能。平台包含自訂商業邏輯例外、以 enum 管理訂單狀態，以及詳細稽核紀錄，方便除錯與監控。

## 需求

### 需求 1

**使用者故事：** 作為顧客，我希望能透過平台下訂單，以便收到餐廳的餐點。

#### 驗收標準

1. 當顧客送出訂單時，系統應建立狀態為 PENDING 的訂單
2. 當訂單建立時，系統應以 INFO 層級記錄訂單細節
3. 若訂單資料無效，系統應拋出自訂 checked 例外並以 WARN 層級記錄
4. 當訂單成功建立時，系統應回傳含唯一訂單編號的確認資訊

### 需求 2

**使用者故事：** 作為餐廳業者，我希望能收到並接受顧客訂單，以便備餐與管理營運。

#### 驗收標準

1. 當餐廳收到訂單通知時，系統應允許餐廳接受或拒絕訂單
2. 餐廳接受訂單時，系統應將訂單狀態更新為 ACCEPTED 並以 INFO 層級記錄
3. 若餐廳關閉或無法接單，系統應拋出 RestaurantUnavailableException 並以 ERROR 層級記錄
4. 餐廳拒絕訂單時，系統應將狀態設為 REJECTED 並通知顧客
5. 若因系統錯誤導致無法接受訂單，系統應以 ERROR 層級記錄例外並維持訂單為 PENDING

### 需求 3

**使用者故事：** 作為外送員，我希望能接受外送任務，以便賺取報酬。

#### 驗收標準

1. 當訂單可外送時，系統應將其開放給外送員指派
2. 外送員接受任務時，系統應將訂單狀態設為 IN_DELIVERY 並以 INFO 層級記錄
3. 若無外送員可用，系統應以 WARN 層級記錄並維持訂單為 READY_FOR_DELIVERY
4. 外送完成時，系統應將狀態設為 DELIVERED 並以 INFO 層級記錄
5. 指派外送失敗時，系統應拋出 DeliveryAssignmentException 並以 ERROR 層級記錄

### 需求 4

**使用者故事：** 作為系統管理員，我希望有完整的日誌與例外處理，方便監控系統健康與除錯。

#### 驗收標準

1. 發生商業邏輯錯誤時，系統應拋出對應 checked 例外
2. 發生系統或執行期錯誤時，系統應處理 unchecked 例外並以 ERROR 層級記錄
3. 正常操作時，系統應以 INFO 層級記錄相關細節
4. 偵測到潛在問題時，系統應以 WARN 層級記錄
5. 發生重大錯誤時，系統應以 ERROR 層級記錄並附完整堆疊
6. 若日誌設定失敗，系統應回退至主控台日誌

### 需求 5

**使用者故事：** 作為開發者，我希望有明確的訂單狀態與自訂例外，方便撰寫可靠商業邏輯並妥善處理邊界情境。

#### 驗收標準

1. 訂單狀態變更時，系統應使用 enum 值（PENDING, ACCEPTED, PREPARING, READY_FOR_DELIVERY, IN_DELIVERY, DELIVERED, CANCELLED, REJECTED）
2. 違反商業規則時，系統應拋出自訂 checked 例外並附說明訊息
3. 發生系統錯誤時，系統應優雅處理 unchecked 例外
4. 嘗試無效狀態轉換時，系統應拋出 InvalidOrderStateException
5. 訂單處理遇到商業邏輯錯誤時，應拋出領域專屬例外

### 需求 6

**使用者故事：** 作為系統操作人員，我希望能追蹤訂單與稽核，以便監控流程並解決顧客問題。

#### 驗收標準

1. 訂單狀態變更時，系統應記錄狀態轉換、時間戳與原因
2. 發生例外時，系統應記錄包含訂單編號與用戶資訊的上下文
3. 偵測到系統效能問題時，系統應以 WARN 層級記錄
4. 發現資料一致性問題時，系統應以 ERROR 層級記錄並採取修正
5. 訂單取消或拒絕時，系統應記錄原因與發起方
